# 事件设计规范

> STS 式随机事件。有得有失，增加单局变数。
> ★ 即时制适配：事件中若涉及战斗，按即时制规则；事件效果（加状态/改属性）需考虑即时制语境。

---

## 设计目标

- 提供风险/收益选择（非战斗的决策点）
- 增加单局变数与叙事感
- 部分事件可作为"流派助推"（给定向卡/遗物）

---

## 一、事件类型体系

| 类型 | 机制 | 例子 |
|------|------|------|
| **选择型** | 2-3 个选项，各有结果 | 献祭 HP 换遗物 / 接受诅咒换卡 |
| **赌博型** | 随机好坏结果 | 开宝箱可能得遗物或受伤 |
| **交易型** | 花资源换资源 | 花 £ 买信息/卡/恢复 |
| **战斗型** | 触发特殊战斗（敌人可有独特规则） | 限时战 / 特殊敌人 |
| **纯叙事** | 无选择，仅展示结果（稀有） | 纯背景叙事 |

---

## 二、事件结果类型

| 结果 | 说明 |
|------|------|
| 加卡 | 给特定卡（常为定向，助推流派） |
| 删卡 | 移除牌（稀有，正面） |
| 遗物 | 给/换/移除遗物 |
| HP 增减 | 恢复/损失 HP（即时制下 HP 跨场，影响大） |
| 金币 | 得/失 £ |
| 状态/诅咒 | 塞入牌组（负面） |
| 最大HP | 永久增减最大HP（强效果） |

---

## 三、★ 即时制适配注意

- **HP 影响**：即时制下 HP 跨场保留，事件扣 HP 会延续到后续战斗，压力大于回合制。需控制扣血幅度。
- **状态/诅咒**：塞入牌组的负面牌，在即时制下是"占能耗/时间"的拖累，比回合制更痛（每轮都打一次）。
- **加卡与排序**：事件加卡同样遵循"随时可排"，不强制排序。
- **战斗型事件**：若触发战斗，按即时制对称规则；可设计"特殊敌人"（见敌人设计规范）。

---

## 四、设计原则

- **风险对等**：高收益必伴高风险
- **可读性**：选项的结果应大致可预测（可标概率）
- **不强制**：多数事件允许"离开"选项（不参与）
- **流派助推**：部分事件给定向卡，帮助玩家确定流派

### 4.1 ★ 战斗型事件规则（已定）

| 规则点 | 规则 |
|--------|------|
| 失败后果 | **死亡**（与普通战斗一致，死局结束单局）——战斗型事件的风险即"败北即败局" |
| 事件敌人 | = 现有敌人模板（HP/回能/卡组，见《敌人卡组数据》）+ **变异规则**（强化倍率/限时/专属牌变体），**不引入新底层机制**（对称性不受影响） |
| 胜利奖励 | 事件专属奖励（非标准三选一），与失败风险对等（如罕见遗物） |
| 限时战变体 | 可设定时（逻辑秒）：限时内击杀→高奖励；超时→敌人撤退战斗结束（**非死亡**），奖励降档 |
| 玩家控制 | 事件可选"离开"不挑战（战斗型不强制） |

> 限时战的意义：本作战斗全自动，限时=**检验构筑输出（DPS）**而非操作，玩家战前自评构筑强度决定是否挑战。示例见《事件数据》【时间裂隙】【被遗忘的决斗者】。
