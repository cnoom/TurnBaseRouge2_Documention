# 表现设计规范

> 定义「观战也要好看」的设计原则与约束。
> ★ 核心挑战：本游戏是**纯挂机自动战斗**，玩家全程观战——表现层的可读性、节奏感、爽快感直接决定体验成败。
> 数值基于逻辑时间（假设表现瞬时），表现层负责「把逻辑结果演好看」，详见《数值框架》§一。

---

## 设计目标

- **可读性第一**：玩家观战后能理解「为什么赢/为什么输」（便于学习构筑）
- **节奏张弛**：不能全程高压或平淡，靠出牌节奏与特效制造起伏
- **确定性不变**：表现只拉长墙钟时间，不改变逻辑结果（见《核心战斗机制》§二.3）

---

## 一、★ 表现形态：对撞分屏（已定）

> 已定：战斗采用**左右对撞分屏**。

```
┌─────────┬─────────┐
│ 玩家    │ 敌人    │
│ HP████  │ HP████  │
│ 能量··  │ 能量··  │
│ 状态⚡毒│ 状态🛡  │
│ [抽牌堆]│ [抽牌堆]│
├─────────┴─────────┤
│   ← 出牌对撞区 →   │
│    牌1  <撞>  牌2  │
└───────────────────┘
```

| 维度 | 规则 |
|------|------|
| 布局 | 左右各占一方（玩家/敌人），中央为出牌对撞区 |
| 信息分区 | 每方独立显示：HP条 / 能量条 / 状态图标 / 抽牌堆（牌背堆叠） |
| 对撞区 | 双方打出的牌从各自一侧飞向中央，碰撞时结算（伤害飘字、特效） |
| 适配 | 1v1 对撞最直观；信息分区清晰，双方状态一目了然 |

---

## 二、可读性约束（来自《战斗设计规范》§五）

| 约束 | 说明 |
|------|------|
| **出牌清晰可见** | 当前双方正在打出/即将打出的牌需有明确视觉指示 |
| **伤害数字飘字** | 必须飘字；特殊效果（穿刺/真实伤害/吸血）有差异化表现 |
| **状态可视化** | 所有 buff/debuff/DoT 必须有图标+剩余时长+层数显示 |
| **能量条** | 连续浮点能量可视化（进度条形式，非离散跳变） |
| **结果可理解** | 战斗回放应能让人复盘「关键转折点」（如某张爆发牌/某次暴毙） |

---

## 三、节奏与 Juice 原则

| 原则 | 说明 |
|------|------|
| **每张牌有演出时间** | 表现层消费"出牌事件"时给足演出时长（飞牌/碰撞/飘字），让每张牌都被看清（逻辑不等表现，演出靠事件队列节奏，见《核心战斗机制》§2.3） |
| **重击有分量** | 高能耗牌/大招的表现更重（屏幕震动/慢放/特效更强） |
| **DoT 有持续反馈** | 毒/灼烧/流血每次跳伤都要有视觉反馈（绿色毒雾/红色灼烧/血溅） |
| **死亡有高潮** | 一方 HP 归零时，结算动画要有仪式感（不只是数字归零） |
| **不加冗余动画** | 每个动画都要传递信息，避免纯装饰性演出拖慢节奏 |

---

## 四、加速/暂停（观战刚需）

> 来自《战斗设计规范》§一：加速/减速/暂停是观战体验刚需，仅调播放速率，不改变逻辑。

| 功能 | 状态 | 说明 |
|------|------|------|
| 暂停 | ✅ 允许 | 便于观察，表现层暂停消费（逻辑照常推进，不阻塞） |
| 加速 | 待定档位 | 观战提速（2x? 4x?），仅加快墙钟、不改逻辑结果 |

> 待定：加速档位具体为 2x/4x 还是其他（见待定事项）。
