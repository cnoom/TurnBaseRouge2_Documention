# 战斗表现机制

> 战斗播放的具体表现规则：逻辑与表现的衔接、各类元素的可视化规范。
> ★ 核心架构：**逻辑层固定 60 tick/s 持续推进、永不暂停**，产出**事件**给表现层独立消费。表现层只负责「把逻辑事件演好看」，不阻塞逻辑（见《核心战斗机制》§2.3、《数值框架》§一）。

---

## 一、逻辑 ↔ 表现的衔接（事件驱动）

### 1.1 核心模型：逻辑产出事件 → 表现层消费

```
逻辑层（60 tick/s 不停，纯确定性）：
   每帧推进 → 能量结算/状态计时/出牌判定
   关键节点产出「事件」入队：
     · 出牌事件(牌A, 目标, 能耗, 效果结果)
     · 伤害事件(来源, 目标, 数值, 类型[普通/穿刺/真实])
     · 状态事件(施加/移除/层数变化)
     · HP变化事件(目标, 变化值)
     · 洗牌事件 / 死亡事件 / 战斗结束
        ↓ 事件队列（FIFO）
表现层（独立节奏消费，不阻塞逻辑）：
   按墙钟节奏从队列取事件 → 演出
     · 出牌事件 → 飞牌动画 + 碰撞特效
     · 伤害事件 → 飘字 + 命中特效
     · 状态事件 → 状态图标动画
   逻辑跑多快，队列就排多长
```

### 1.2 关键特性

| 特性 | 说明 |
|------|------|
| **逻辑永不暂停** | 逻辑层固定 60 tick/s，不被表现阻塞；数值基于逻辑时间，与表现时长完全解耦 |
| **表现层滞后是正常的** | 表现层消费速度可能慢于逻辑产出（尤其加速档位下），表现为「看完整录像」，信息不丢 |
| **加速 = 快进看录像** | 加速档位下表现层更快消费事件，所有动画都播但更快；逻辑结果不变 |
| **回放友好** | 存「种子+输入」或「事件流」即可重跑——逻辑重产出相同事件，表现层重播，100% 一致 |
| **调试友好** | 可纯跑逻辑（不依赖表现）验证平衡/复现 bug |

### 1.3 表现追赶策略：闸门背压=冻结（2026-08-19 起）

> 演进史：v1「队列排队消费」（回放连续走、闸门滞后排队）→ v2「闸门背压=冻结」（演出中墙钟停走，
> 2026-08-16）→ v3「速率曲线+钳制」（时间变稠，2026-08-17）→ v4「回退冻结」（本版，2026-08-19）。
> 回退原因：逻辑时间轴不含演出时长（事件间隔=纯充能时间），v3 让演出期间的墙钟蠕进"预支"了
> 充能间隙——当 *演出墙钟时长 ≥ 充能间隙*（回能快/卡便宜/演出链长）时，出牌冲拳结束时
> `PlaybackTime` 已被钳制边界顶到下一次出牌时刻，充能环瞬间又满、出牌连珠炮，
> "敌方出牌后环还是满的"即此。冻结语义下演出与充能互不侵占，间隙全额可见。

> **机制**（`CombatPlaybackDirector.Tick` ← `presentation.HasPendingWork` 探针，CombatLauncher 接线）：
> - **空闲 1x**：闸门无未结算事件时墙钟秒 == 逻辑秒，能量环匀速充、DoT 按设计节奏走。
> - **闸门忙=冻结**：闸门有已入队未结算的事件（演出中/事件后停顿/积压待消费）时墙钟**完全停走**——
>   环满 = 出牌事件派发 = 冲拳/攻击开始，演出期间时钟与充能静止，结算放行后恢复 1x，
>   充能环从余能起步、全额可见地重新充能。
> - **动画 showcase 慢放（与墙钟解耦）**：表现动画（DOTween `Sequence.timeScale`）与飘字
>   （`duration ÷ rate`）按 `CombatPacingConfig.SlowdownRate(事件 Severity)` 放慢**自身时长**
>   （Minor=1x / Normal≈0.9 / Major≈0.35 / Kill≈0.2）——大招/击杀演出更有分量感，
>   但不再作用于回放墙钟（v3 曾"世界与动作同速"，v4 起只有动作慢、世界停）。
> - **命中帧编舞**：受击抖动与伤害飘字延迟到攻击方前冲的命中帧
>   （`attackDuration × attackImpactFraction`，随速率÷rate 拉长）才触发——数字在"拳头到达"瞬间出现，
>   替代旧"出拳与挨打同拍开始"；DoT（无来源）等立即触发。
> - **同拍多段连击**：多段攻击（HitCount）同刻的后续命中，攻击者改播半幅快拳（lunge×0.4/duration×0.6），
>   多段从"结巴"变"连打"；每段仍有独立飘字与受击。

### 1.4 快照（Snapshot）

- 表现层可定期请求/接收**状态快照**（双方 HP/能量/状态/牌堆的完整状态）
- 用途：表现层对齐当前真实状态（如切屏回来、跳转回放进度时快速同步）
- 快照不替代事件流，是事件流的辅助（断点对齐用）

## 二、对撞分屏的信息布局（已定）

> 形态见《表现设计规范》§一。此处定义各信息元素的可视化规范。

### 2.1 每方信息区（玩家/敌人对称）

| 元素 | 可视化规范 |
|------|-----------|
| **HP 条** | 横向血条，扣血有缓动动画；HP 数字叠加显示；致死伤害有闪红预警 |
| **下一张牌常驻槽** | 出牌位（原出牌弹窗位，屏上半部两角对称）常驻显示该阵营下一张要出的牌（NextCardSlot 驱动 CardShow，弹窗卡即常驻卡——出牌演出为快速冲拳后原地换牌，无入场/出场三段式）；卡牌能耗徽章外圈的**充能环**填充 = 当前能量 / 该牌能耗，体现**连续浮点累积**（平滑增长，非离散跳变），战斗开局（BattleStart 快照基线）即开始走环；**满环脉冲在本方出牌演出（冲拳）开始时触发（谁执行谁脉冲）**——同拍双满时等待方满环常亮、待闸门轮到自身冲拳才脉冲；Energize（回能加速）期间环转金色（回能速率→攻击频率变化直接可见） |
| **状态图标行** | 每个 buff/debuff/DoT 一个图标；图标上叠层数 + 剩余时长（环形或数字） |
| **抽牌堆** | 牌背堆叠显示，张数可见；堆顶牌打出时有「抽走」动画 |
| **弃牌堆** | 折叠显示张数（次要信息） |

### 2.2 中央对撞区

| 元素 | 可视化规范 |
|------|-----------|
| **出牌飞行** | 牌从所属方飞向中央，对方为目标 |
| **碰撞结算** | 碰撞瞬间触发：伤害飘字 + 命中特效 |
| **伤害飘字** | 普通（白）/ 穿刺（紫）/ 真实伤害（黄）/ 吸血（绿） |
| **状态施加** | 施加 debuff/DoT 时，目标状态行有「新增图标」弹出动画 |

> 注：本游戏无暴击（A1 已定），故无暴击飘字。

## 三、各类卡牌/状态的表现规范

| 类别 | 表现要点 |
|------|---------|
| **基础攻击牌** | 简洁快速，轻量命中特效 |
| **高能耗大招（8-12费）** | 重击分量：屏幕轻微震动、慢放、更强特效 |
| **多段攻击** | 每段独立飘字 + 命中（体现段数） |
| **穿刺** | 紫色飘字 + 无视护甲的视觉（直贯 HP 条） |
| **护甲获得** | 角色周围护盾光环；护甲衰减时光环渐隐 |
| **力量/敏捷** | 角色身上常驻增益光效 |
| **易伤/虚弱** | 目标身上 debuff 光效（易伤=红、虚弱=灰） |
| **毒** | 绿色毒雾 + 每 1s 跳伤飘字（绿） |
| **灼烧** | 红色燃烧 + 每 0.5s 跳伤飘字（红，高频） |
| **流血** | 血溅粒子 + 每次受攻击牌伤害触发额外飘字（深红） |
| **荆棘** | 反伤时反弹粒子（刺状） |
| **能力牌** | 打出时有「永久生效」的仪式感（如铭刻光效） |
| **消耗牌** | 打出后牌碎裂消失（区别于进弃牌堆） |

## 四、节奏控制

| 场景 | 表现策略 |
|------|---------|
| 前期（TTK短） | 出牌快、特效轻，节奏紧凑 |
| 后期（TTK长） | 大招有分量、DoT 持续反馈，节奏有起伏 |
| 濒死（HP<30%） | 血条闪红、紧张音效（预警） |
| 击杀瞬间 | 死亡动画 + 结算（仪式感） |
| 洗牌（抽牌堆空→重洗） | 短暂的「洗牌」动画（提示进入新一轮） |
