# 核心战斗机制

> 即时制、全自动、1v1 对称卡牌对撞的底层规则。
> 核心：双方各自**实时回能 → 按抽牌堆顺序自动出牌 → 抽/弃/洗循环**，战前固定排序，战中纯自动。

---

## 设计目标

- 把 STS 式的卡牌构筑深度，用"即时自动播放"的形式呈现
- 双方规则**完全对等**，战斗本质是"两条出牌时间轴的对撞"
- 保证确定性：相同卡组顺序 + 相同回能参数 + 相同洗牌种子 = 可复现结果

---

## 一、战斗总体形态

| 维度 | 规则 |
|------|------|
| 对战形态 | **1v1**，玩家 vs 单个敌人 |
| 对称性 | **完全对称**——敌人也用 抽牌堆/弃牌堆/洗牌/回能/自动出牌 的同一套机制 |
| 时间模型 | 实时 **60 tick/s**，双方**完全并行**（各自独立回能、可同时出牌，无行动权交替） |
| 玩家干预 | **仅战前排序卡组**；进入战斗后顺序锁定、纯自动（无大招、无走位、无战中调整） |
| 胜负条件 | 任一方 HP 归零 |

> 战斗的"即时感"不来自操作，而来自**能量恢复速率 × 卡牌能耗**所形成的出牌节奏。

---

## 二、★ 核心机制：卡牌循环与能量

这是整个战斗系统的引擎。玩家与敌人共用同一套规则。

### 2.1 三个牌堆

| 牌堆 | 作用 |
|------|------|
| **抽牌堆**（Draw Pile） | 按**玩家战前排序的顺序**（敌人按预设顺序）从顶部取牌打出。**确定性序列**。 |
| **弃牌堆**（Discard Pile） | 打出的牌（无特殊情况）进入此处。 |
| 手牌 | **本游戏无传统手牌概念**——牌不进入"手"，而是"能量够就直接从抽牌堆顶打出"。 |

### 2.2 出牌循环

```
能量实时恢复（如 +N/s）
        │
        ▼
能量 ≥ 抽牌堆顶牌的能耗？ ──否──→ 继续等待回能
        │是
        ▼
扣除能量，打出抽牌堆顶牌（执行卡牌效果）
        │
        ▼
该牌进入弃牌堆
        │
        ▼
抽牌堆是否为空？
        │是
        ▼
将弃牌堆洗乱后成为新的抽牌堆，继续循环
        │
        ▼
……直到一方 HP 归零
```

### 2.3 出牌结算（逻辑不暂停 + 事件产出）

- **逻辑结算**：能量判定为"够"的那一帧，完成该牌的逻辑——结算卡牌效果、扣除能耗、把该牌移入弃牌堆、检查下一张牌堆顶。
- **★ 逻辑永不暂停**：逻辑层固定 60 tick/s **持续推进**，**不被表现阻塞**。出牌、伤害、状态变化等关键节点由逻辑层产出**事件（event）**入队，表现层独立消费。
- **表现层独立消费事件**：表现层维护**事件队列**，按自己的节奏从队列取事件演出（飞牌/飘字/特效）。表现层**永不阻塞逻辑**——逻辑跑多快，队列就排多长。
- **数值基于逻辑时间**：所有数值平衡（回能/状态/TTK）基于「逻辑时间」建模——逻辑时间是纯固定步长的时间流（60 tick/s 不停），与墙钟时间/表现时长完全解耦。回能 8/s 指"逻辑秒"。
- **回放友好（架构优势）**：逻辑是纯确定性的时间序列。回放只需存「种子+输入」或「事件流」重跑，逻辑重产出相同事件 → 表现层重播。调试也能纯跑逻辑（不依赖表现）。

> 关键规则：**逻辑单向产出事件 → 表现层消费**。一张牌打出 → 逻辑产出"出牌事件"入队 → 逻辑继续推进下一张 → 表现层稍后取事件演出。表现层滞后于逻辑"现在"是正常的（尤其加速档位下），观感=看完整录像，信息不丢。详见《数值框架》§一、《战斗表现机制》§一。

#### 事件/快照模型（设计要点）

| 项 | 说明 |
|----|------|
| **事件（Event）** | 逻辑产出的不可变记录，如 `出牌(牌A, 目标, 伤害15)` / `状态施加(毒, 2层)` / `HP变化(-15)` / `死亡` |
| **快照（Snapshot）** | 某时刻的完整状态快照（双方HP/能量/状态/牌堆），用于表现层对齐/跳转，也用于断点回放 |
| **事件队列** | 表现层消费的 FIFO 队列；表现层按墙钟节奏消费，逻辑持续入队 |
| **确定性** | 相同输入（卡组顺序+回能参数+种子）→ 相同事件流 → 相同回放 |

### 2.4 关键推论

- **能耗 = 出牌的时间成本**：一张耗 8 能的牌，需积攒对应时间才能打出；高能耗牌打得慢但强。
- **出牌序列由"排序 + 洗牌"共同决定**：首轮严格按战前排序；进入第二轮及之后，因洗牌引入随机性。
- **牌组是循环播放的引擎**：一副牌会被反复洗乱播放，因此牌组的整体节奏比单张强度更重要。
- **战前排序是首轮的确定性策略点**：排在前面的牌会更早、且在每轮洗牌前率先打出。

## 三、能量机制（连续浮点累积）

> ★ 核心：能量**不是离散跳变**（`+2/+3`），而是**分散到每一帧连续增加**。这是本战斗节奏可预测性的根基。

### 3.1 每帧回能公式

```
每帧能量增量 = 回能速率 / 60   （单位：点/逻辑帧）
当前能量 += 每帧能量增量        （浮点累积，不取整）
```

例：回能速率 `8.0 点/逻辑秒` → 每帧 `+0.1333`。能量是浮点数，逐帧累加，**永不取整、永不离散跳变**。

> 注：逻辑层固定 60 tick/s 持续推进，不被表现阻塞（回能属逻辑，正常累积）。故所有"秒"指**逻辑秒**。

### 3.2 出牌判定（连续浮点比较）

每次逻辑推进（帧）：
```
while 当前能量 ≥ 抽牌堆顶牌能耗:
    结算该牌效果（→ 逻辑产出"出牌事件"入队，逻辑继续推进，不等待表现）
    当前能量 -= 该牌能耗       （浮点扣减，保留余数）
    该牌移入弃牌堆
    （抽牌堆空则洗牌，见 §五）
    （检查下一张是否也能打——单次推进可能连出多张）
```

### 3.3 帧级示例（回能 8/s，即 +0.1333/帧）

| 帧 | 能量变化 | 堆顶能耗 | 动作 |
|----|----------|----------|------|
| N | 3.6 → 3.73 | 4.0 | 不够，等待 |
| N+2 | 3.87 → 4.0 | 4.0 | **够！出牌** → 能量扣至 0.0，该牌进弃牌堆（产出"出牌事件"，逻辑继续） |
| N+3 | 0.0 → 0.4 | 4.0 | 不够，等待（从0重新累积） |
| N+30 | 3.73 → 3.87 | 4.0 | 不够 |
| N+32 | 3.87 → 4.0 | 4.0 | **够！出牌** → 能量扣至 0.0（约30帧=0.5s逻辑后打出下一张） |

### 3.4 关键特性

- **能量几乎不浪费**：因为是浮点连续比较，牌恰好在"够"的那一帧打出，余数（如 12.27 扣 12 = 0.27）保留到下一张。
- **出牌间隔完全可预测**：单张牌的出牌间隔 ≈ `能耗 ÷ 回能速率`（逻辑秒）。基础牌能耗 4 / 回能 8 = 0.5 逻辑秒打一张。
- **贪婪连出（消除能量积压的核心机制）**：每次逻辑推进时，出牌判定是 **while 循环**——只要能量还够打下一张，就连续结算多张，能打就打、贪婪消耗。因此能量一旦达标就会被即时打掉，**不存在能量积压需要上限处理的情形**。（注：逻辑持续 60 tick/s 不停，出牌事件即时产出，故论证成立。）
- **浮点精度**：使用浮点累积，但浮点误差在固定 tick + 固定运算顺序下**确定性可复现**（见 §八）。不做"四舍五入"等会破坏确定性的处理。

### 3.5 能量上限（已定：无上限）

> ★ 已定：**能量无上限，不处理溢出。** 因为出牌是贪婪即时的（§3.4），能量达标即被打掉，没有积压生存空间。

- 出牌判定为 while 循环，能量足够就连续出牌直到不够为止，能量被持续消耗。
- 唯一边角：**能耗为 0 的牌**打出不扣能量，能量仍会因回能而增长——但这是**有益的**：攒下的能量随时可被能耗>0 的牌消耗，也为未来"消耗所有能量造成伤害"这类卡牌留出设计空间。
- 结论：不设上限，不做溢出判定，实现更简、确定性更纯。

## 四、对称性原则

### 4.1 规则对等
玩家与敌人共享：抽牌堆/弃牌堆/洗牌循环/能量与回能/自动出牌逻辑。

### 4.2 差异来源
不同的敌人 = **不同的卡组配置 + 不同的能量/回能参数**，而非不同的底层规则。
- 例：一个"快攻敌人"= 低能耗牌多 + 回能快；一个"Boss"= 高能耗大招 + 中速回能 + 特殊机制牌。

### 4.3 设计意义
战斗深度 = **"我的卡组时间轴" vs "敌人卡组时间轴"** 的对撞。策略核心在构筑（卡组组成 + 战前排序），而非战中操作。

---

## 五、洗牌规则（首轮确定性 + 后续随机）

> ★ 已定：**首轮严格按战前排序；第 2 轮起完全随机洗牌。** 这形成"首轮可设计、后续随机"的节奏结构。

| 轮次 | 抽牌堆顺序 | 说明 |
|------|-----------|------|
| **第 1 轮** | **严格 = 玩家战前排序** | 这是玩家唯一的确定性策略点。排前的牌必先打、且在洗牌前率先打完一整轮。 |
| **第 2 轮及之后** | **完全随机洗牌** | 弃牌堆→洗乱→新抽牌堆。顺序不再可控，靠 PRNG 种子决定（仍确定性可复现）。 |

### 设计含义
- **首轮是"表演你设计的引擎"**：玩家精心排序的序列会在开场精确执行一次，是策略的高光时刻。
- **后续是"引擎的自然循环"**：洗牌后进入随机播放，玩家无法再精确控制顺序——这鼓励玩家追求**整体节奏稳健的牌组**，而非依赖特定顺序的组合。
- **平衡杠杆**：若想强化排序策略，可让首轮更"长"（如牌组大）；若想强化随机，可缩小牌组加快进入第 2 轮。
- **★ 法则遗物篡改洗牌**：【法则】遗物使弃牌堆回填抽牌堆时**不再洗牌**（保持打出顺序），让战前排序的价值延伸到全程。详见《遗物数据》。

## 七、状态结算顺序

> 详见 [状态体系](状态体系.md) §二。每次出牌触发伤害时，按以下顺序在当帧瞬时完成：
>
> ① 基础伤害 → ② 攻击方修正(力量) → ③ 受击方修正(易伤/虚弱) → ④ 最终伤害合成 → ⑤ 护甲扣减(优先扣Block,超出扣HP) → ⑥ 受击后触发(反伤/抽牌等) → ⑦ 死亡判定

## 八、确定性原则（重要）

- 逻辑固定 60 tick/s，渲染帧率与逻辑分离。
- **能量浮点累积**：每帧 `+= 回能速率/60`，不取整；浮点误差在固定 tick + 固定运算顺序下确定性可复现。
- 所有随机（第 2 轮起的洗牌等）使用**种子驱动的 PRNG**，按 tick/出牌顺序消耗随机数。
- **逻辑瞬时**：出牌当帧即结算，不引入施法延迟，状态机最简、可复现性最强。
- **事件流可复现**：相同输入产出相同事件流，回放=重跑逻辑产出事件+表现层重播（见 §2.3）。
- 目标：相同输入（卡组顺序 + 回能参数 + 种子）可复现整场战斗，便于调试、平衡与回放。
