## Context

当前文档仓库的模块内文件为平铺排列，目录结构没有区分文档的类型层级（规范/机制/数据/校验）。两个文件超过 200 行限制。所有文件引用使用模块根目录的相对路径，重构后路径将统一前移一层。

## Goals / Non-Goals

**Goals:**
- 在每个模块内部建立 01_规范/02_机制/03_数据/04_校验 四层子目录
- 将所有现有文件按类型归入对应层级
- 拆分敌人幕间强度.md（434行→3个文件）和事件系统.md（431行→4个文件）
- 为 03_进度与成长、05_体验与表现 创建预留空层
- 更新所有内部引用路径

**Non-Goals:**
- 不修改任何游戏机制、数值、设计内容
- 不改变 00_总纲/ 的平铺结构（术语表/数据字典作为 L0 跨层数据）
- 不修改文档内容逻辑，仅做物理重组和路径修正

## Decisions

### 1. 子目录编号方案：01/02/03/04 前缀

- 使用「编号_层名」格式，与模块编号风格统一（如 `01_规范/`）
- 与现有模块编号体系保持一致，读者无需学习新约定
- 排序上规范→机制→数据→校验的阅读顺序与编号递增一致

### 2. 敌人幕间强度拆分方案：按敌人类型切割

- 拆为：幕间增长原则（~60行）+ 普通敌人增长曲线（~200行）+ 精英与Boss增长曲线（~170行）
- 归入 03_数据/敌人幕间/ 子目录，与 03_数据/敌人配置数据/ 并列
- 两者设计用途不同：幕间 = 设计师查看演变全貌；配置数据 = 实现者查看具体数值

### 3. 事件系统拆分方案：按类型/用途切割

- 拆为：事件设计规范 + 事件流程机制 + 正面事件池 + 混合事件池
- 设计原则/类型体系/属性锚点 → L1 规范
- 触发流程/高危版规则/连续事件链 → L2 机制
- 20+2个事件的数据明细 → L3 数据（按正/混合拆为两个文件）

### 4. 00_总纲保持平铺

- 术语表和数据字典是跨层 L0 数据，不参与模块内分层
- 数据字典（242行）超出 200 行限制，但作为 SSOT 保持单个文件完整性

### 5. 旧文件处理方式

- 被拆分的源文件（敌人幕间强度.md、事件系统.md）→ 移入 归档/ 目录，不在原位删除
- 被移动位置的文件（如卡组构筑规范.md）→ 直接移动到新路径，不在旧路径留副本

## Risks / Trade-offs

| 风险 | 缓解措施 |
|------|---------|
| 路径变更过多，遗漏更新内部引用 | 建立清单逐项核对；数据字典的「影响文档」列作为检查指南 |
| 拆分后新文件内容与旧文件有出入 | 拆分时逐段对照旧文件，确保零改动搬运，仅做结构重组 |
| 拆分后文件间的交叉引用需重建 | 在新文件头部的「关联章节」标注目标文件路径 |
| 图层层数过多导致导航深度增加 | 四层为固定标准，不允许多层嵌套；数据子目录最多二级 |
