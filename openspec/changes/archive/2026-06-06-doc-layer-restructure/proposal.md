## Why

当前文档仓库在模块内部是平铺结构，规范、机制、数据、校验四类文档混排在同一目录下，没有层级区分。两个文件（敌人幕间强度 434行、事件系统 431行）严重超过 200 行限制。模块间的文档类型边界模糊，新手和贡献者难以快速定位目标文档。03_进度与成长、05_体验与表现两个模块仅有 README 提及，无实际目录结构。

## What Changes

- 在每个模块内建立四层子目录：`01_规范/`、`02_机制/`、`03_数据/`、`04_校验/`
- 将现有 ~20 个文件按类型归入对应层级
- **拆分** `01_核心战斗/敌人幕间强度.md`（434行）为 3 个文件：
  - `03_数据/敌人幕间/幕间增长原则.md`
  - `03_数据/敌人幕间/普通敌人增长曲线.md`
  - `03_数据/敌人幕间/精英与Boss增长曲线.md`
- **拆分** `02_局外系统/事件系统.md`（431行）为 4 个文件：
  - `01_规范/事件设计规范.md`
  - `02_机制/事件流程机制.md`
  - `03_数据/正面事件池.md`
  - `03_数据/混合事件池.md`
- 为 `03_进度与成长`、`05_体验与表现` 创建四层空目录（预留）
- 更新 README.md 导航链接、数据字典影响文档列中的路径引用

- `03-module-placeholders`: 03_进度与成长、05_体验与表现的预留空层目录创建
